## Project Overview

An end-to-end retail analytics project on the Walmart Store Sales Forecasting dataset (Kaggle).
The project covers the full data science pipeline — from exploratory data analysis and feature
engineering to machine learning models and an interactive Power BI dashboard.

**Core business problem:** Predict weekly department-level sales across 45 Walmart stores
and identify what drives high vs low performing weeks.

## Dataset

**Source:** [Walmart Store Sales Forecasting — Kaggle](https://www.kaggle.com/competitions/walmart-recruiting-store-sales-forecasting)

| File | Description | Rows |
|---|---|---|
| train.csv | Weekly sales per store and department | 421,570 |
| stores.csv | Store type (A/B/C) and size | 45 |
| features.csv | Markdowns, CPI, temperature, unemployment | 8,190 |

**Date range:** February 2010 to October 2012
**Stores:** 45 | **Departments:** 81 | **Total weeks:** 143

> The data/ folder is excluded from this repository. Download the dataset from Kaggle and place all CSV files in the data/ folder before running the notebooks.

## Phase 4 — XGBoost Regressor

**Notebook:** `notebooks/04_XGBoost_Final_v2.ipynb`

**Task:** Predict exact weekly sales dollar amount per Store-Department-Week

**Correct time series pipeline:**
```
TimeSeriesSplit CV (4 folds, WMAE scoring)
        ↓ finds best parameters
Train XGBoost on full training data
        ↓
Evaluate once on holdout test set (Aug-Oct 2012)
```

**Best parameters found via TimeSeriesSplit CV:**
- n_estimators: 500 | max_depth: 7 | learning_rate: 0.1
- subsample: 0.8 | colsample_bytree: 0.8

**Final Results:**

| Metric | Value |
|---|---|
| R2 | 0.9863 |
| MAE | $1,250 |
| RMSE | $2,572 |
| MAPE | 16.76% |
| WMAE | $1,339 |

**Model Comparison:**

| Model | R2 | MAPE | WMAE |
|---|---|---|---|
| XGBoost Final | 0.9863 | 16.76% | $1,339 |
| Linear Regression | 0.9765 | 56.88% | $2,058 |
| Naive Baseline | 0.9484 | 41.60% | $2,535 |
| Raw Features Only | 0.0926 | 651.75% | $14,199 |

**XGBoost beats naive baseline by 47.2% on WMAE** — confirming genuine forecasting beyond historical averages.

**Note on lag_52:** lag_52 (same week prior year) was intentionally excluded.
Including it achieves R2 of 0.987 but creates a near-trivial prediction problem.
The final model uses lag_1, lag_4 and rolling features — a more realistic and challenging setup.

## Phase 5 — Classification Models

**Notebook:** `notebooks/05_XGBoost_Classifier.ipynb`

**Task:** Predict whether a Store-Department-Week will be HIGH or LOW sales
relative to each store-department's own historical median.

- **Target:** Sales_Class (1 = High, 0 = Low)
- **Class balance:** 49.9% High, 50.1% Low — perfectly balanced
- **No class imbalance handling needed**

**Pipeline:**
```
TimeSeriesSplit CV (4 folds, ROC-AUC scoring)
        ↓ finds best parameters
Train on full training data
        ↓
Evaluate on holdout test set
```

**Final Results:**

| Model | Accuracy | F1 | ROC-AUC |
|---|---|---|---|
| XGBoost Classifier | 76.72% | 0.754 | 0.851 |
| Random Forest | 73.77% | 0.726 | 0.816 |
| Logistic Regression | 67.30% | 0.705 | 0.756 |

**Accuracy by store type:**
- Type A: 77.2% | Type B: 76.5% | Type C: 75.2%

**Business value:**
- High confidence HIGH predictions → increase staffing and inventory
- High confidence LOW predictions → run promotions and markdowns
- Complements the regression model which predicts exact dollar amounts

## Leakage Prevention

Every step of this project was built with strict leakage prevention:

| Step | How leakage was prevented |
|---|---|
| Train-test split | Strict date-based cutoff — Jul 27 2012 |
| Store/Dept means | Computed on training data only (not full dataset) |
| Lag features | shift() computed within each Store-Dept group |
| Rolling features | shift(1) applied before rolling window |
| Hyperparameter tuning | TimeSeriesSplit CV — no future data in any fold |
| eval_set | Not used during XGBoost training |
| Standard scaler | Fit on training data only |

**Verification:** Training R2 (0.945) is lower than test R2 (0.981) confirming zero overfitting and no meaningful leakage.
